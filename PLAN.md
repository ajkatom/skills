# Plan: Remediate the Dark Factory security/capability audit — DETECTION-GRADE (final)
_Round 3 revision by Claude — owner chose detection-grade + all grade-independent hardening_

## Goal

Remediate all 10 audit findings + the capability-claim critique across M28–M38 via the subagent pipeline, CRITICALs first. Owner decisions: **(1) four distinct intervention modes; (2) security gates mandatory at `standard`+ with signed, scoped, expiring waivers; (3) DETECTION-grade assurance** (after Codex proved prevention-grade against a hostile same-user process is architecturally unreachable in a single-user stdlib skill without a privileged service / off-host infra — a different product, out of scope).

**Threat model (detection-grade), stated precisely.** In-model adversaries: the **confined builder/candidate** (a sandboxed, in-band process that may try to escape or teach-to-the-test), **accidental mutation**, and a **buggy or hostile security gate** that runs over the artifact. Guarantee: the qualified artifact is content-addressed and every consumption (final exam, gates, sign, custody attest, verify, handoff) reads it **by digest and fails closed on any mismatch** — so what is attested/shipped is provably what was tested, or the run refuses. Read-only access, hostile-metadata rejection, and atomic publish are **defense-in-depth** against the in-model adversaries (they genuinely stop the confined candidate and accidents). **Out-of-model residual, documented plainly:** a hostile process running as the *same OS user* as the supervisor, or a compromised supervisor holding the signing key, can forge — this is the identical trust boundary `finalize_manifest` already documents for cooperative/standard; enterprise raises it with split-custody + off-box WORM but does not eliminate same-user-on-host. Prevention of that class needs a privileged CAS/signing service under a separate user/off-host, off-host approver keys, authenticated remote WORM + timestamp, fs-verity — captured separately as a future infra spec (`references/prevention-grade-roadmap.md`), not built here.

Confirmed against `main` @ `3f843e2`: DF-01 (input snapshot only); DF-03 (`env=None` + adapters require key & self-set header + `df_proxy` injects only when header absent, `do_CONNECT`→501, `NO_PROXY` never cleared, hostname-only origin); `df_security._run_external_gate` runs `cwd=workspace` unconfined; `run_scenarios` inherits full `os.environ`; Linux sandbox `--ro-bind / /` exposes host FS read-only; resume selects newest `state.json`.

## Approach

### M28 — Seal-first content-addressed artifact (Critical; DF-01 + DF-07 + read-only gates)
1. **`df_seal.freeze(output_dir) -> object_id`**: FD-relative `openat`/`O_DIRECTORY|O_NOFOLLOW` traversal with before/after `fstat` inode checks; reject symlink/special/multi-link, **setuid/setgid/world-writable files and world-writable/setgid dirs** (fail-closed). Copy into a private temp dir, `fsync`, then **atomic no-overwrite publish** — `renameat2(RENAME_NOREPLACE)` on Linux / `renamex_np(RENAME_EXCL)` on macOS via `ctypes`, **fail closed** where the primitive is unavailable (#10); if the target digest exists, byte-validate and reuse. Canonical manifest is an **external sidecar** keyed by digest, covering every path incl. **empty dirs**, normalized file+dir modes, size, sha256; `object_id = sha256(sidecar)`. **The sidecar is the atomic commit record** — an object dir present without a valid sidecar is quarantined/recovered, never reused (crash-safety, R4 #13).
2. **Defined deliverable (#9):** builder writes only into a dedicated **output directory**; writes to reserved supervisor paths rejected. `spec.md`/prompt/feedback are control-plane, recorded separately, never shipped.
3. **Two projections (#1):** builder projection (no holdouts) + verifier projection; **the verifier/holdout object is never mounted into a candidate sandbox**. Staged bundle: initial builder-policy bundle at start + append-only derived verifier bundle after brownfield characterization (#21-R2); each id recorded; the bundle binds the **digest-pinned gate/build env image** (#19,#20-R2 — image digest resolved+sealed here).
4. **Order of ops:** converge → freeze+publish artifact → final exam + gates against the object in a **dedicated gate sandbox** (artifact read-only, isolated report dir, sanitized env, NO control-plane/key mounts, default-deny network, full process teardown — R4 #2) → qualify → sign manifest (`artifact_object_id`, projection/bundle ids, env digest) → custody attaches to `object_id` under the control-root lock → handoff re-verifies by digest.
5. **`terminalize()`** single exit; accepts an already-sealed id, **forbids a second freeze after final verification begins** (#11); validates schema invariants; signs; anchors; clears state once.
6. **Single qualification state machine (#29-R1; R5 #3 resolved):** one authoritative outcome — `qualified = barrier_isolation ∧ host_isolation ∧ control_plane ∧ app_security ∧ current_waiver_validity`. The sub-states (`barrier_qualified`, `host_isolation_qualified`, `control_plane_qualified`, `app_security_qualified`) are derived, and a tier that meets some-but-not-all emits a **distinct non-qualified outcome code** (e.g. macOS-`standard` that holds the barrier but can't close keychain/DNS Mach-IPC → `barrier_qualified=true, host_isolation_qualified=false` → overall NOT `qualified`, code `HOST_ISOLATION_LIMITED`) — never an ambiguous partial "qualified." **Waiver validity is re-evaluated at every verification** (never a frozen boolean): at **enterprise** it requires a signed remote timestamp receipt (fail closed if unavailable); at standard/hardened it uses local-time expiry with the same-user-forgeable residual documented (waivers are digest-bound to `artifact_object_id`+`gate_report_digest`, so not replayable across artifacts) (#13,#14, R4 #5).
7. **Object retention (#27):** refuse deletion of a referenced object; verifying a pruned run → explicit "artifact unavailable", never a pass.
8. **Verify/attest by identity:** `verify_manifest(run_dir, artifact_object=…)` recomputes the sidecar over the object and requires `object_id` equality at each consumption; **a pre-M28 manifest returns a distinct `UNBOUND` non-success status** that custody and handoff refuse (never a silent exit-0 "approved", R4 #15).
9. **Tests:** boundary race-injection (freeze/publish/gate/sign/attest/verify/handoff each fail closed on swap), concurrent publisher, and the acceptance case (change one byte/mode/name/empty-dir → verify fails; a gate that writes the artifact fails closed). Honest note in tests: these prove in-model detection, not same-user prevention.

### M29 — Candidate isolation, host-read + egress + process-tree (Critical, staged)
- **29a:** full process-tree teardown for every scenario type (CLI+HTTP). Linux uses a **PID namespace / cgroup** for reliable reaping (killpg alone is escapable via `setsid`/double-fork, R4 #3); macOS uses the best available containment and is marked **limited** where descendants can't be reliably reaped (feeds the `host_isolation_qualified=false` outcome).
- **29b — env/IPC sanitization (#12):** launch candidates with a minimal allowlisted environment; strip `SSH_AUTH_SOCK`, proxy vars, secrets, loader/language vars; deny inherited Unix sockets / agents / credential brokers. Applies at every tier.
- **29c — host-read isolation at `standard` via default-deny sandbox (#2-R2,#13,#15):** replace `(allow default)+deny-control-root` and Linux `--ro-bind / /` with **default-deny** — a fresh Linux mount+PID namespace with explicit minimal binds (private `/proc`, private `/tmp`, no host-root bind); a macOS default-deny profile with a **designed, probed per-runtime allowlist**. Probe-verified fail-closed; no Docker required at standard. **Honest macOS limit (#14):** keychain/`securityd` and `mDNSResponder` DNS ride Mach IPC that file-denial can't close — either deny those Mach services or mark standard-macOS host-isolation as *limited* (documented), never overclaimed.
- **29d — copy-on-run scratch per scenario (#11,#12; R5 resolved):** each scenario gets a FRESH writable copy of the verified artifact object (copy → run → discard), so apps that create DBs/caches/sockets work while the object itself is never mutated. Portable (no OverlayFS privilege; OverlayFS is an optional Linux-hardened optimization). **Scenario independence is a validated contract** — cross-scenario state handoff must use an explicit twin/fixture, never shared-workspace mutation.
- **29e — candidate egress default-DENY at all qualifying tiers, no "unrestricted+warning still qualifies" (#3-R2):** macOS uses `loopback` restricted to a **run-specific exact-port allowlist** — only the twin/verifier ports assigned to THIS run are reachable on `127.0.0.1`; all other loopback ports (host Redis/DBs/browser-debug/credential-proxy/etc.) are denied and the denial is probed (R5 #1). **Linux — DECIDED topology (R5 #2 + R6): namespace-local verifier AND twins.** The HTTP-scenario poll client executes INSIDE the candidate's per-scenario network namespace so a loopback-bound candidate service is reachable, with no route out of the namespace (no veth to the host, external egress denied by construction). **Each twin a scenario requires has its LISTENING SOCKET launched inside that SAME netns** (so the candidate reaches it on `127.0.0.1`), while the twin's **definition, observation log, and verifier controls remain OUTSIDE the candidate's mount + PID namespaces** — twin-backed scenarios work, and the holdout barrier + M12 twin-evidence integrity hold (the candidate cannot see or tamper with the observation log). The spec pins namespace ownership, the empty allowed source/dest set to the outside, teardown, and non-vacuous probes (external denied, in-namespace loopback + twin reachable, observation log unreachable from the candidate). Unrestricted candidate egress ⇒ not qualified.
- **29f — candidate container at hardened/enterprise:** minimal rootfs, only the artifact object mounted, sanitized env, no host home/SSH/cloud/Docker-socket, default-deny egress + allowlist proxy, torn down per cohort; verifier/holdouts in a separate isolated context.

### M30 — DF-03 transport-correct proxy path (High)
Adapter proxy mode: plaintext HTTP to the local proxy carrying the absolute `https://` target (not urllib CONNECT). Supervisor passes a **read-only-mounted proxy descriptor** (endpoint, provider, allowed origin, header mode) whose digest is bound into sealed policy; per-run capability token in `Proxy-Authorization`. `df_proxy` enforces a **strict canonical `(scheme, host, port)` origin** — one canonical parser rejecting ambiguous userinfo/IPv6/IDNA/percent-encoding/trailing-dot forms — **plus provider-specific method/path (+ body-size/request-count) policy** so the injected credential can't be used against arbitrary provider APIs (R4 #7); it **connects to the validated pinned IP** with preserved Host/SNI + cert validation (closes the DNS-rebinding interval, R4 #8), and **clears `NO_PROXY`**. Config load validates adapter↔host↔allowlist↔header as one coherent provider config. Live integration test through the proxy with no provider key in the builder; fail-closed on direct egress. (Same-user residual on the token/descriptor documented, not claimed prevented.)

### M31 — DF-04 usable enterprise `df_init` scaffold (High; R4 #14 resolved — no contradiction)
Two explicit modes, never a half-usable middle: (a) **enterprise answers MUST supply operator off-host approver PUBLIC keys + a conforming authenticated remote WORM sink endpoint** — init generates the blocks with **secret references** (never local approver private keys, #5-R3) and runs an **operational preflight that reads back an anchored object and confirms active retention/Object-Lock** (not mere reachability, #6-R3); or (b) absent those inputs, init emits an **explicitly NON-enterprise development config** (clearly-marked dev sink, `assurance != enterprise`) that cannot claim enterprise assurance. A fresh clone can complete either path and pass `load_config` + preflight without manual file surgery. Validate-before-mutate.

### M32 — DF-05 per-run egress verification (High)
A **mandatory local transport/lock probe** (deterministic; exercises the plaintext-to-proxy inject path + netns/iptables lock + `(scheme,host,port)` + capability token) before any builder invocation; a **distinct optional paid provider probe** (#25-R2). Record probe result + policy/env digest on the manifest; abort fail-closed when unverified/stale.

### M33 — DF-06 mandatory gates + signed waivers (High; R4 #10 resolved — no fork)
Per-tier **immutable minimum gate set** (config may strengthen, never disable); gates must pass for `app_security_qualified`. **Gate runtime — DECIDED:** at **`standard`** gates run on the HOST inside the M29 default-deny gate sandbox (artifact read-only, isolated report dir, sanitized env, no control-plane/key mounts, default-deny network, full process teardown) — **no Docker, and no "digest-pinned env" claim at standard**; at **hardened/enterprise** gates run in the **digest-pinned container** and the env digest is bound into the manifest. (A gate that fabricates its OWN verdict is operator-trust/garbage-in — out of what any harness prevents; "hostile gate" in-model = mutation/escape, which the gate sandbox confines.) Waiver = canonical signed event binding `run_id + artifact_object_id + gate_policy_digest + gate_report_digest + normalized_finding_fingerprint + signer_policy + anchored issuance/expiry`; validity re-checked at every verification (enterprise: signed remote timestamp; standard/hardened: local-time + documented residual); **tier-independent waiver-signer allowlist/threshold**. `WAIVER_PENDING` resumable phase (uses the M36 FSM).

## Key decisions & tradeoffs
1. **Detection-grade, verify-by-digest at every consumption; same-user residual documented, not overclaimed.** Read-only/atomic/capability-token are defense-in-depth against the in-model (confined candidate, accidents), not claimed proof against a same-user adversary.
2. **`standard` host-read isolation via default-deny OS sandbox** (fresh namespace, no host-root bind, minimal probed allowlist) — no Docker; honest macOS Mach-IPC limit.
3. **Copy-on-run scratch per scenario** (portable, no OverlayFS privilege) so writing apps run while the artifact stays immutable; scenario independence is a validated contract.
4. **Enterprise custody stays operator-supplied off-host keys + a real, readback-verified WORM sink**; local scaffolds are explicitly dev/non-enterprise.
5. **FSM before gates, after Criticals**; ONE authoritative `qualified = barrier ∧ host_isolation ∧ control_plane ∧ app_security ∧ waiver_validity` with distinct non-qualified codes for limited tiers; waiver validity always re-evaluated at runtime.
6. **Standard gates run host-sandboxed (no Docker); hardened+ gates run in the digest-pinned container.** macOS-standard is barrier-qualified but honestly `host_isolation_qualified=false` where keychain/DNS Mach-IPC or descendant reaping can't be closed.
